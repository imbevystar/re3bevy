# Arena construction and original inputs

- Arena automobiles follow the same boundary: ArenaAutomobileSpawn consumes
its car into production component owners; ArenaAutomobileRuntime is QueryData,
never a Component holding an owned car. Audio borrows concrete/physical/input
state readonly and writes only its audio owners; allocate physical audio
identity in the preceding audio-domain phase. ArenaVehicleSettings owns only
the fixture's handling/parameters, not a duplicate live vehicle.
Arena construction distinguishes expected unsupported kinds from required
input failures. Required model/handling/surface/DFF/COL/wheel inputs retain a
named failure counter; a failed request allocates no actor and does not advance
model colours. SURFACE.DAT loads must validate the five native triangular rows:
`-` means zero adhesion; invalid numbers or missing cells cannot become unit grip.
ArenaRandomState owns one continuing native CGeneral stream for the isolated
arena's app lifetime. Construction, control, damage, effects and fallback
player creation borrow it. Do not put another seed in vehicle settings or
parsed asset data; spawn, retirement, asset reload and arena reopen never reset
it. Validate authored wheel inputs before construction consumes random values.
